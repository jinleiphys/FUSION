# kb-wiki: what these pages are, and where they come from

This directory holds 61,187 generated pages, one per paper in the arXiv
nucl-th corpus, plus topic pages and the citation and relation layers that
connect them. It is the knowledge base FUSION ships with, so that a question
about the literature can be answered offline instead of by a web search.

**These pages are not written by the papers' authors, and they are not a
substitute for reading the papers.** Every claim on a page should be checked
against the source before it is relied on or cited.

## What is on a page, and who wrote it

| Part | Origin |
|---|---|
| `arxiv`, `doi`, `title`, `authors`, `date`, `categories` in the frontmatter | arXiv metadata, unmodified |
| The quoted block under the title | the paper's own abstract, verbatim |
| `## Key claim`, `## Method`, `## Key numbers`, and the rest | generated by a large language model reading the paper, NOT by its authors |
| `concepts` | assigned by lexical matching against the PhySH taxonomy |
| `## In-corpus citations`, `## Related work` | derived from citation context within the corpus |

The generating model and the date are recorded on every page as
`digest_model` and `digest_date`, so a page can always be traced to how it was
made. **Do not strip the frontmatter**: it is the provenance.

Machine-generated summaries get things wrong. Numbers can be misread, a claim
can be overstated, and a relation between two papers can be asserted where the
authors intended none. Treat a page as an index into the literature, not as
evidence.

## The basis for distributing this

- **Metadata and abstracts** come from arXiv, which makes its metadata
  available for reuse and offers it under CC0 through its API and OAI-PMH
  interface. Each page links back to the paper by arXiv id and DOI so a reader
  is one click from the authoritative version.
- **The digest sections** are new text produced by a model; the extracted
  quantities are facts drawn from the paper.
- **The papers themselves are not here.** No LaTeX source, no PDF, no
  full-text database. Those are read locally when the corpus is built and are
  never redistributed by this project. If you want the paper, follow the link.

This is the project's own reading of the position, offered so you can judge it
for yourself; it is not legal advice.

## If you are an author and you want your page gone

Open an issue, or email the maintainer, and say which arXiv id. The page will
be removed, with no argument and no request for a reason. The same applies to
a publisher acting for an author.

## Rebuilding this yourself

The generation pipeline is in `scripts/` (`run_full_digest.sh` and
`run_full_relations.sh` for the bulk jobs). Rebuilding the full corpus is a
paid API job, run in an off-peak window; the project measured roughly USD 109
for one full pass. You do not need to rebuild it to use FUSION.

## Citing

Cite the paper, never the page. If you need to say where a summary came from,
name FUSION and give the arXiv id, and make clear that the summary is
machine-generated.
